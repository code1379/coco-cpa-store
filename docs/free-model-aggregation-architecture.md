# 免费模型聚合架构方案

本文是 `coco-cpa-store` 的个人开发计划。目标是把多家免费额度模型统一接入 CLIProxyAPI，同时允许用户选择性启用订阅或付费模型；本仓库当前只做开发、测试和构建，不自动发布插件商店。

## 目标与边界

- 运行时以 CLIProxyAPI 原生 Go 插件为主，不把 FCC 的 Python 服务整体搬进来。
- 以 FreeTier 2API 的供应商适配器和宿主接入方式作为聚合底座。
- 参考 Free Claude Code (FCC) 的供应商抽象、模型元数据、模型目录刷新、失败分类、重试和回退设计。
- 保留现有六个 Whexy 插件作为独立包，并保留自己的 Playground 插件。
- Cline 不再重复实现为第二个独立 Provider：FreeTier 2API 已有 Cline 适配。只有在验证发现确实缺少功能时，才扩展该适配器。

## 参考项目

- FreeTier 2API: https://github.com/jiandanc/CLIProxyAPI-freetier2api-plugin
- FCC: https://github.com/Alishahryar1/free-claude-code
- Whexy 插件仓库: https://github.com/whexy/whexy-cpa-store

## 从 FreeTier 2API 复用的底座

FreeTier 2API 已提供多供应商 Go 适配器、凭证隔离、OAuth/API Key 接入、动态模型发现、统一控制台、模型启停、别名、跨供应商负载均衡和故障转移。它的 Cline 适配器已经包含 WorkOS 设备码授权、Token 刷新、免费/订阅模型分类以及流式 Chat Completions 转发。

第一阶段应先验证并整合现有实现，而不是再写一套平行的 Cline OAuth、模型目录和请求转发逻辑。

## 从 FCC 借鉴的设计模式

这里只借鉴可观察的架构与行为，不直接复制 FCC 源码：

1. **统一供应商契约**：每个供应商实现一致的模型发现、请求执行、清理和能力描述接口。
2. **归一化模型元数据**：统一保存模型 ID、显示名、供应商、模型类别、上下文窗口、最大输出、工具调用、推理和输入模态等信息。
3. **动态目录与缓存**：刷新模型目录时记录每家供应商的成功或失败；单家目录暂时不可用时保留上次成功结果，并在有依据时使用兜底目录。
4. **明确的错误分类**：区分认证/权限错误、请求参数错误、限流、过载、网络超时和上游临时错误。
5. **有边界的重试与回退**：只对可重试的暂时性错误重试；认证失败、权限拒绝和无效请求不应盲目切换。流式响应已向客户端发送内容后，不能不加判断地切换供应商重放请求。
6. **可诊断性**：记录供应商、请求模型、实际返回模型、尝试次数、耗时、状态码和用量；避免记录访问令牌或敏感请求正文。
7. **供应商策略与合规状态**：对供应商接入方式、服务条款限制、可用区域和已知风险做显式记录；当上游不再允许某种接入方式时，应能禁用对应适配器。

## 免费、订阅和付费模型策略

模型分类必须优先使用上游目录提供的明确分类或可靠的计费元数据，不能只根据模型 ID 是否包含 `free` 来猜测。

建议的统一分类：

- `free`: 免费额度模型，默认启用。
- `subscription`: 订阅权益内的模型，默认禁用，用户手动启用后才能请求。
- `paid`: 按量计费或可能产生额外费用的模型，默认禁用。
- `unknown`: 无法确认计费属性的模型，默认禁用并显示“未确认”，避免意外产生费用。

模型禁用必须在服务端请求执行前强制检查，不能只在 UI 中隐藏模型。

### Cline 的已知差距

FreeTier 2API 当前的 Cline 模型解析读取 `recommended`、`free` 和 `clinePass` 三类；我们之前实测的 Cline 推荐模型响应还可能出现 `clineCloud` 分类。因此应在实际接口响应确认后，补齐该分类的解析，并映射到明确的订阅/付费策略。

对免费模型的请求按已验证的 Cline 接口行为添加 `X-CLIENT-TYPE: cline-cli`。这个头是客户端标识，不是认证凭证；当前测试成功不代表该非公开接口未来会一直可用。必须保留清晰错误、超时和模型可用性诊断，且不得把服务端明确禁止的模型访问当成长期保证。

## 推荐运行架构

```text
客户端（Claude Code / Codex / Cline / 其他 OpenAI 或 Anthropic 兼容客户端）
                          |
                          v
                CLIProxyAPI 原生接口
                          |
                          v
              FreeTier 2API 聚合插件
                          |
            +-------------+-------------+
            |             |             |
            v             v             v
       Cline 适配器   Qoder/Trae 等   API Key 提供商
            |             |             |
            +-------------+-------------+
                          |
                          v
            统一模型目录、账号调度和执行结果
                          |
             +------------+------------+
             |                         |
             v                         v
        Playground                 用量/日志诊断
```

FCC 的策略不需要成为一个额外的运行时代理。它的模型元数据、错误分类、重试/回退和诊断思路可以逐步移植到 FreeTier 2API 的 Go 适配层和聚合层中。

## 仓库布局建议

- `plugins/client-keys/`、`extra-models/`、`model-groups/`、`opencode-go/`、`system-prompt/`、`usage-dashboard/`: 现有上游插件，继续独立维护。
- `plugins/freetier2api/`: 待评估迁入的聚合插件，保留其 MIT 许可与原作者声明。
- `plugins/cli-playground/`: 我们自己的独立模型测试插件。
- 不单独增加 `cline-provider`，除非后续证据表明必须独立部署 Cline。

迁入 FreeTier 2API 前，先验证源码、测试、插件 ABI、Nix 构建和跨平台产物。不要在第一次迁入时顺便重构所有供应商。

## 许可证边界

- FreeTier 2API 仓库声明 MIT 许可证；迁入时保留其 LICENSE、版权和使用限制。
- FCC 使用 AGPL-3.0-only。不要直接复制 FCC 源码到 MIT 插件中。可以参考公开的架构行为并独立实现；若未来确实要移植 FCC 代码，应先评估并明确相应组件和整体分发的许可证义务。
- Whexy 仓库根目录没有统一的 LICENSE 文件。虽然其插件元数据声明 MIT，继续修改/分发上游插件前仍需核实实际授权范围。
- 上游平台自己的服务条款独立于代码许可证。只允许个人使用的供应商适配器，应遵守其个人用途限制；不要提供公开共享池或转售能力。

## 分阶段实施

1. **基线验证**：确认当前 `coco-cpa-store` 的 GitHub Actions 能运行 `nix flake check` 并产出现有插件的 ZIP artifact。
2. **聚合插件迁入评估**：确认 FreeTier 2API 的完整目录、测试、ABI、Nix 依赖和 MIT 声明；在独立分支迁入，不直接改主分支。
3. **行为测试**：对每个供应商验证登录、模型发现、流式/非流式调用、模型启停、失败分类和凭证刷新。
4. **Cline 分类完善**：核实并补齐 `clineCloud` 等模型分类，免费默认启用，订阅/付费/未知默认禁用。
5. **FCC 风格增强**：逐项增加规范化能力元数据、目录刷新状态、错误分类、有界重试和安全回退。
6. **Playground 整合**：保留独立插件，测试聚合插件暴露的模型，并显示请求模型、实际模型、耗时、状态码和用量。
7. **只构建不发布**：GitHub Actions 执行格式检查、测试、构建 ZIP 并上传短期 workflow artifacts；不自动打 tag、不创建 GitHub Release、不更新商店 registry。

## 验收标准

- 免费模型默认启用；订阅、付费和计费属性未知的模型默认禁用。
- 禁用模型的请求在服务端执行前被拒绝。
- 模型目录刷新失败不会静默清空最后一次成功目录。
- 认证/权限错误不会触发无意义的跨供应商重试。
- 流式请求不会在已经向客户端输出部分内容后盲目重复执行。
- 所有接入供应商有独立测试；不在日志或测试产物中泄露真实凭证。
- GitHub Actions 只生成可下载的构建 artifact，不发布插件商店。
